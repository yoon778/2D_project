## 작업 흐름

1. 지휘가 목적·담당 파일·연결 규격·완료 기준을 담아 작업 지시
2. 로직·UI 담당이 연결에 필요한 조건과 변경 영향을 지휘에 보고
3. 지휘가 차이를 조율한 뒤 담당 파일별로 구현 진행
4. 담당자가 변경 파일·검증 결과·남은 한계·다른 담당에게 필요한 연결을 보고
5. 지휘가 실제 변경과 실행 증거를 점검하고 필요하면 수정 요청
6. 검증된 작업 단위마다 지휘가 중간 커밋, 업로드 요청 시 푸시

개발 채팅의 결과는 지휘가 확인·전달하며, 두 개발 채팅이 서로 직접 작업을 지시하지 않음
지휘가 메시지·상태 확인 도구로 두 채팅을 관리하는 범위는 이 프로젝트의 작업 지시·진행 확인·검토·수정 요청
공유 Git 인덱스 충돌을 막기 위해 stage·commit·branch·push는 지휘만 수행
기존 파일·사용자 변경을 보존하고, 과거 중간 작업을 소급 생성하지 않음
작업 브랜치는 planning/first-presentation을 유지하며 커밋 메시지는 `<type>: <한글 설명>` 형식, 푸시는 사용자 업로드 요청 시에만 진행

## 현재 2.5D 계획과 유지할 연결 규격

아래는 새 구현의 합의 기준이며 현재 코드에 적용되었다는 뜻이 아님. 이전 탑뷰의 발 조사·배치 보정은 중단하고 2.5D 표현 기준으로 대체

- Game.start/restart/step/swing/interact/is_visible/pop_events 공개 API 유지, 변경 필요 시 먼저 지휘에 보고
- Python/pico2d와 2D 지면 이동·충돌·소음·추격 규칙을 유지. 실제 3D 엔진·Blender·실제 z축 이동·옥상·발판 상자는 추가하지 않음
- 수직 정수리 탑뷰 대신 앞·옆·등과 다리가 보이는 고정 사선(3/4) 2.5D로 계획. 참고 그림의 가방은 시점·분위기 참고이며 장비·인벤토리 규칙 추가가 아님
- 좌표는 왼쪽 아래 원점의 지면 px, 시간은 초, 조준 각도는 rad. 새 표현에서 world(x,y)는 발바닥 접지점이며 충돌과 깊이 기준으로 공유
- UI가 지면→화면 배치와 화면 마우스→지면 조준 좌표 변환을 한 경계에서 담당. 화면 위치를 지면 좌표로 그대로 넘기는 가정을 없애고 양쪽 변환을 함께 검수
- 세운 스프라이트는 발점 pivot을 사용하고, 캐릭터·오브젝트의 앞뒤 순서는 같은 발점 깊이 규약으로 정렬. 벽의 충돌·시야 차단용 지면 영역은 공유하되 그림 실루엣과 분리
- 한 방향 원본을 360도 회전하는 방식은 새 캐릭터에 사용하지 않음. 초판은 4방향 기본 포즈와 짧은 보행·공격 모션, 안정 후 8방향 확장
- 이동 방향과 조준 방향을 분리하고 실제 변위로 보행을 계산. 전진·스트레이프·후진·정지·벽에 막힌 입력·재시작의 발 접지와 방향 선택을 검수
- 전체 스프라이트 좌우 반전으로 방향을 대체하지 않음. 모든 방향에서 왼손 택배·몸 앞 운반, 오른손 방망이·가슴등 유지
- Event(kind, x, y)는 UI가 프레임당 한 번 소비, 상태 판정은 로직 담당
- 손전등 지면 부채꼴·벽 가림은 같은 range/half_angle/walls 기준을 사용. 지면 조명 패스와 세운 캐릭터의 노출 패스를 분리해 허리·머리가 바닥 마스크에 잘리지 않도록 설계
- 노출 패스를 분리해도 시야 밖·벽 뒤 좀비와 체력·?·! 표시는 숨김. 정교한 3D 빛·그림자는 초판에 추가하지 않음
- SpatialAudio.update(game, focused) 후 이벤트 재생, 시야 판정으로 소리를 차단하지 않음
- 좀비 소리 전용 채널 6·7, 자동 효과음 채널 8~15 유지
- Renderer.close가 SDL 종료 전에 오디오·이미지·텍스처·글꼴 해제
- 4방향별 크기·발점 pivot·장비 부착점·최소 프레임 규격은 실제 2.5D 에셋 제작 전에 지휘를 통해 합의
- 기본 1맵·1좀비·1배달·방망이 1종, 총 없음. 기존 이동·스태미나·5타·0.4초 제자리 경직·암흑·건물 윤곽·벽 가림·거리 음향 규칙은 PRD대로 유지
