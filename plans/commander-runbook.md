# Dead Route 지휘 실행 절차

기준일: 2026-11-05
기획 기준: [PRD](../PRD.md) · 개발 순서: [로드맵](development-roadmap.md) · 소유권: [채팅 운영](team-workflow.md)

## 1. 반드시 지킬 진행 방식

한 번에 작은 작업 묶음 하나만 진행함
지휘가 두 담당 채팅에 지시하고 결과를 연결한 뒤 **1차 검수·수정·재검수** 수행
통과한 실행본을 중간 커밋하고 **사용자 2차 확인을 받을 때까지 다음 묶음 착수 금지**
사용자 지적은 같은 묶음의 수정 작업으로 처리하고 지휘 재검수 후 다시 사용자에게 전달함
사용자가 확인을 끝내고 다음 진행을 명시한 뒤에만 다음 묶음을 배정함
사용자 답변이 없거나 시간이 지났다는 이유로 승인 처리하지 않음

2026-11-04 최초 요청은 절차 문서화와 첫 작업 R1-A 착수를 허용한 상태였음
사용자의 컴퓨터 사용 요청으로 일시중단한 뒤 `아까 하던거 마저 진행해` 요청으로 R1-A 지휘 검수를 재개함
R1-A 이후 작업은 아래 사용자 확인 절차를 따름

## 2. 역할과 연결 경로

| 역할 | 맡을 일 | 변경 가능한 범위 |
| --- | --- | --- |
| 지휘 | 범위·연결 규격 확정, 지시, 통합 검수, 수정 요청, 사용자 인계, Git | AGENTS.md, PRD.md, README.md, plans/, 검수에 필요한 연결 수정 |
| 로직 채팅 | 지면 이동·충돌·보행 위상·전투·AI·소음·거리 음향·판정 테스트 | game/core.py, game/locomotion.py, game/spatial_audio.py, game/requirements.txt, game/tests/test_core*.py, game/tests/test_locomotion*.py |
| UI·에셋 채팅 | 실행 창·입력 연결·화면 변환·캐릭터·모션·맵 표현·시야 | game/main.py, game/player_visual.py, game/visibility.py, game/assets/, game/tests/test_visual*.py |
| 사용자 | 2차 실제 조작·외형·재미 확인, 수정 요청, 다음 작업 허용 | 지휘에게 피드백 |

담당끼리 공용 상태·규격을 임의로 바꾸지 않고 지휘에게 전달함
같은 작업 폴더를 사용하므로 담당 파일만 수정함
담당 밖 변경이 필요하면 이유와 필요한 입력·출력을 먼저 지휘에게 보고함
stage·commit·branch·push·reset·checkout은 지휘만 실행함

기존 채팅 식별자는 [채팅 운영](team-workflow.md)의 표를 사용하며 새 채팅을 만들지 않음
담당별 결과 보고는 `plans/handoffs/<작업ID>-logic.md`, `<작업ID>-ui.md`에 작성함
소유권 표의 예외로 로직은 자기 `*-logic.md`, UI는 자기 `*-ui.md` 보고서만 작성 가능하며 다른 plans/ 문서는 지휘 소유임
검수 증거는 무시되는 `output/review/<작업ID>/`에 저장하고 보고서에 실제 경로·명령·결과를 기록함
스크린샷·테스트 로그를 실제 조작·청취 결과처럼 보고하지 않음

## 3. 한 묶음을 진행하는 정확한 순서

1. **상태 확인** — 지휘가 현재 브랜치·미커밋 변경·이전 사용자 피드백 확인
2. **작업 확정** — 작업 ID, 목표, 담당 파일, 연결 규격, 제외 범위, 완료 기준 작성
3. **규격 공유** — 같은 문서와 규격을 두 채팅에 전달하고 담당 밖 변경 금지 명시
4. **개별 제작** — 각 담당이 자기 범위 구현·자체 확인·결과 보고 후 정지
5. **연결 확인** — 지휘가 함수·입력·좌표·에셋 발점이 일치하는지 확인
6. **1차 검수** — 지휘가 변경 비교, 필요한 자동 검사, 실제 실행 화면·조작 확인
7. **수정 반복** — 문제의 재현 방법·기대 결과·담당을 적어 재지시하고 영향 범위 재검수
8. **중간 커밋** — 1차 통과 결과와 사용자 확인 항목을 기록하고 검증한 파일만 커밋
9. **2차 인계 후 정지** — 실행 명령·직접 확인할 항목·알려진 한계·커밋을 사용자에게 전달
10. **사용자 확인** — 지적이 있으면 7번으로 돌아감, 통과와 다음 진행 요청이 있으면 완료 기록 후 다음 묶음 배정

자동 조작이 입력되지 않거나 실제 화면·소리를 확인하지 못한 항목은 `미확인`으로 기록함
필수 검수가 실패하면 `1차 통과`로 표시하지 않고 해결하거나 미해결 사유를 사용자에게 명확히 전달함
담당의 자체 확인만으로 지휘 1차 검수를 생략하지 않음

## 6. R1-A 기준 규격 이력

목표: 실제 pico2d 창에서 한 방향 임시 캐릭터를 움직이며 사선 장면의 발점·조준·벽 가림 확인
이 묶음에는 보행 애니메이션·몸의 4방향 전환·전투·좀비·스태미나·손전등 마스크·배달을 넣지 않음
캐릭터는 방향 샘플 1개로 고정하고 연속 조준은 별도 지면 표식으로 확인함
한 방향 샘플임을 화면과 사용자 인계에 명시하며 최종 방향 전환 기능으로 보고하지 않음

| 연결 항목 | R1-A 규격 |
| --- | --- |
| 실행 | 프로젝트 루트에서 `.\.venv\Scripts\python.exe game/main.py` |
| 창 | 1280×720, 제목 `Dead Route - R1-A` |
| 지면 | 왼쪽 아래 원점, 960×720 지면 px, 발 접지점이 player.x/y |
| 화면 변환 | screen_x = 160 + world_x, screen_y = 90 + 0.60 * world_y, pico2d 왼쪽 아래 원점 |
| 마우스 | SDL 위쪽 원점 y를 먼저 아래쪽으로 변환한 뒤 화면→지면 역변환 |
| 시작·크기 | player=(480,180), 충돌 반경 14 지면 px, 도트풍 캐릭터 표시 높이 128 화면 px |
| 이동 | WASD, 지면 90px/s, 대각선 정규화, 입력과 조준 분리 |
| 시간 | 초 단위, 실행 루프의 프레임 dt는 최대 0.05초로 제한 |
| 벽 | 지면 직사각형 Wall(400,330,220,60), 화면상 세운 높이 110px는 UI 소유 |
| 깊이 | 높은 지면 y부터 낮은 y 순으로 그리기, 벽 기준은 아래쪽 밑변 y |
| 입력 해제 | 포커스를 잃으면 이동 입력 초기화, Esc·창 닫기로 종료 |
| 에셋 | 고정 사선 도트풍, 왼손 몸 앞 택배·오른손 방망이·가슴등의 한 방향 임시 PNG, 실제 원본 크기·발점 기록, 전체 회전·좌우 반전 금지 |
| 표시 | 발점과 조준 지면 표식을 개발 확인용으로 표시, 공격·빛 구현으로 표현하지 않음 |

`game/core.py`의 공통 API는 다음으로 고정함

```python
WORLD_WIDTH = 960.0
WORLD_HEIGHT = 720.0
WALK_SPEED = 90.0
PLAYER_RADIUS = 14.0

@dataclass
class Wall:
    x: float
    y: float
    width: float
    depth: float

@dataclass
class Player:
    x: float = 480.0
    y: float = 180.0
    aim_angle: float = math.pi / 4
    moved: bool = False

def move_player(player: Player, axis_x: float, axis_y: float,
                dt: float, walls: Sequence[Wall]) -> None: ...

def aim_player(player: Player, target_x: float, target_y: float) -> None: ...
```

`aim_angle`은 지면 +x 기준 반시계 rad, 같은 위치를 조준하면 기존 각도 유지
`moved`는 마지막 이동 갱신의 실제 변위 여부이며 벽 앞 제자리 입력에서는 False
UI는 이 API를 import하며 core는 pico2d/SDL·화면 변환에 의존하지 않음
충돌은 지면 벽 직사각형과 반경을 고려하고 월드 바깥으로 발점이 나가지 않도록 제한함
API 변경은 지휘가 문서에 반영하고 두 채팅 모두에게 알린 후 적용함

### R1-A 지휘 1차 재현 항목

1. `.venv\Scripts\python.exe -m compileall -q game` 및 현재 작업의 논리·화면 변환 검사 실행
2. 실제 SDL 창을 열어 1280×720 장면·한 방향 샘플·발점·벽·범위 안내를 확인
3. 정지·상하좌우·대각 이동·키 해제 확인, 조준을 바꿔도 이동 방향이 따라 바뀌지 않는지 확인
4. 벽 아래에서 접근·옆면을 따라 이동·벽 뒤쪽으로 우회, 충돌 영역과 보이는 밑변 비교
5. 벽 앞에서는 캐릭터가 앞에, 벽 뒤에서는 벽이 앞에 그려지는지 확인
6. 마우스를 상하좌우로 옮겨 조준 표식의 위치와 좌표 역변환 확인
7. 다른 창으로 전환한 뒤 복귀할 때 이동 입력이 남지 않는지 확인
8. Esc와 창 닫기를 각각 확인, 사용자 실행본은 정상 시작 위치로 다시 열어 인계 가능

검수 수단을 함께 기록함: 자동 판정, 자동 SDL 사건, 네이티브 창 관찰, 네이티브 자동 입력, 사용자 실제 입력
한 수단의 통과를 다른 수단의 통과로 바꾸어 기록하지 않음
1차 통과는 해당 묶음의 지정 범위에만 적용하며 방향 전환·애니메이션 완성을 뜻하지 않음

### R1-A 사용자 2차 확인 항목

1. 캐릭터의 크기·발 위치·몸 앞 택배·오른손 방망이가 자연스러운지 확인
2. WASD로 움직이고 벽에 접근했을 때 발이 떠 보이거나 벽 속으로 들어가는지 확인
3. 벽 앞과 뒤를 오가며 가림이 자연스러운지 확인
4. 마우스로 조준 표식을 바꾸며 화면과 지면 위치가 어긋나는지 확인
5. 한 방향 고정 샘플의 시점·크기를 확정할지, 수정할지 전달

피드백 예: `R1-A: 캐릭터를 조금 작게`, `R1-A: 벽 뒤에서 발이 보임`, `R1-A 확인 완료, R1-B 진행`
수정 요청을 받으면 해당 묶음을 `수정 중`으로 바꾸고 지휘 재검수와 사용자 재확인을 반복함
