## 완료한 준비

미사용 이전 시제품·기획·PPT·에셋·임시 출력·캐시를 삭제하고 현재 사용하는 문서와 참고 그림만 남겼습니다.
개발용 가상환경과 로컬 수업 가이드를 유지합니다. 사용자의 계속 개발 지시로 R1-B 4방향·짧은 보행을 연결하고 발 교대·상체 흔들림을 수정했습니다.
사용자 요청의 S1·S2와 1주차 전체 검수를 마쳐 네 방향 모두8장 보행을 적용했습니다. 자동79개·Windows렌더·실제 표시창30초 성능·native입력/재시작3회 통과 기록은 [1주차 baseline](handoffs/r1-week1-review.md)에 보존.
[W1 낮은 보행](handoffs/r1-weight-review.md)·[W2 착지](handoffs/r1-weight-landing-review.md) 이후 발 과속 피드백에 따라 [보행 박자·발 연결](handoffs/r1-walk-cadence-review.md) 보완. 90px/s·주기64px 유지. 도트풍 승인 뒤 사용자 요청의 R1-C8에서 상하좌우를 추가해8방향·72자세로 확장. 다음 단계 착수 전 실제 조작감2차 확인.
현재 R1-C8-WALK에서 승인한 공통 원화로8방향 보행을 다시 연결함. 정지/상체 픽셀·체형 유지와 게임 검수는 [공통 원화 보행 기록](handoffs/r1-consistent-walk-review.md) 참조.

현재1주차의 사용자 요청으로 R2-ZA12 좀비 공격8→12자세·중간32개를 추가함. 기존64키/생산 코드/판정 보존·전체156개·Windows96상태/8실공격·회피·취소·추격복귀/기존64키·8복귀 실제화면0차이·표시창10초 검수 완료. [현재 검수](handoffs/r2za12-zombie-attack-review.md)·[계약](r2za12-zombie-attack-contract.md) 참조. 사용자2차 확인 대기이며 전체R2와 나머지 주차 완료를 뜻하지 않음.

[개발 기록](weekly-development-log.md)에 실제 수행·검수·커밋을 남깁니다. 커밋은 `feat: R3 달리기와 스태미나 적용`처럼 단계와 한글 설명을 포함합니다.
[지휘 실행 절차](commander-runbook.md)에 따라 각 작은 묶음을 지휘 1차 검수·수정·커밋한 후 사용자 2차 확인에서 멈춥니다. 사용자 확인과 다음 진행 요청 뒤에만 다음 묶음으로 넘어갑니다.

## 1주차 R1 완료 기준과 이력

R1-A 한 방향 샘플 뒤 R1-B 4방향 보행, S1 한 방향8장, S2 나머지3방향8장, 실제 루프 검수 순으로 진행했습니다. [S2 계약](r1b-smooth-s2-contract.md)·[1주차 검수 계약](r1-week1-validation.md)·[지휘 실행 절차](commander-runbook.md)를 따릅니다.
사용자의 1주차 전체 순차 진행 요청에 따라 내부 단계·검수·커밋을 마쳤습니다. 실제 물리 키보드·주관적 보행 체감은 사용자2차 확인으로 남습니다. 나머지 주차별 체크포인트는 유지합니다.

1. 지휘가 화면 크기·지면↔화면 변환·발점·장비 부착점·입력 계약을 확정합니다.
2. UI는 임시 캐릭터와 벽 하나로 접지·연속 조준·깊이를 검증합니다. 한 방향 샘플을 확인하고 4방향으로 늘립니다.
3. 로직은 필요한 지면 이동·충돌만 연결합니다. 과거 코드는 Git 이력에서 읽고 의존성을 확인한 함수부터 재사용합니다.
4. 지휘가 정지·전진·후진·옆걸음·방향 전환·벽 앞 정지·실제 창을 확인한 뒤 완료 처리합니다.

R1-C8의8방향은 사용자 요청으로 승인한 보완입니다. 정교한 추가 모션·3D 도구·여러 좀비는 이 묶음에 넣지 않습니다.

- R1 뒤 로직 판정과 UI 방향별 모션 제작을 병행할 수 있습니다. 임시 에셋 규격은 먼저 공유합니다.
- R3 뒤 R4를 연결하고 R2~R4 검증 후 R5를 통합합니다. 소유권은 [협업 규칙](team-workflow.md)을 따릅니다.

## 검증과 복구

- 새 파일 생성 후 `.venv\Scripts\python.exe -m compileall -q game`으로 문법 확인
- 필요한 판정 테스트는 game/tests/에 추가, 구 테스트는 새 계약에 맞춰 검토 후 활용
- 구 테스트는 이전 코드에 대한 이력이며 현재 실행 대상이 아닙니다. 새 코드의 계약에 맞는 테스트와 렌더 검증을 구현 단계에서 작성합니다.
- 자동 검증·실제 창·실제 키보드·출력 장치 청취를 구분해서 보고
- 실패한 단계의 담당 변경만 직전 커밋과 비교해 수정, 사용자 변경 덮어쓰기 금지
- 마지막에는 추가 적·새 맵·8방향 이상·정교한 아트보다 배달 완주·전투·소음·암흑·재시작 우선
