# 그림자 배달 개발 계획

작성일: 2026-11-02
상태: 주인공 아틀라스 적용, 맵·좀비는 임시 도형
기획 기준: [PRD.md](../PRD.md)
작업 루트: 2D_project
게임 개발 폴더: game/
이 문서의 소스·맵·리소스·테스트 경로는 game/ 기준, 문서·발표 자료와 .venv는 저장소 루트 기준

## 1. 목표와 현재 상태

목표는 지도 1개·좀비 1마리·야구방망이 1종·택배 배달 1건을 끝까지 플레이하는 기본판
성공·체력 소진 실패·결과 화면 재시작까지 연결

확정 방향:
- 탑뷰, 지상 한 층
- 왼손은 몸 앞의 택배, 오른손은 방망이, 가슴 부착등은 초기 구현안
- 마우스 조준과 WASD 이동 분리
- 손전등 밖은 완전 암흑, 건물 윤곽만 희미하게 표시
- 보이지 않는 좀비 소리는 들리고, 공격 소음은 좀비의 조사 대상
- 발판 상자·옥상·높이 전환 삭제

현재 확인한 상태:
- game/main.py와 core.py에 첫 프로토타입 구현, 지도는 core.py에 고정 배치
- visibility.py의 광선 경계와 화면 마스크로 손전등 340px·80도·건물 가림 구현, 타격 밀림 대신 제자리 0.4초 경직
- 소음 조사·건물 우회·도착 후 수색과 스태미나 달리기 추가, 좀비 체력 5타로 조정
- 걷기·좀비 90px/s, 달리기 135px/s, 스태미나 100·초당 25 소모·20 회복
- 주인공 탑뷰 아틀라스 적용, 맵·좀비는 임시 도형과 합성 효과음 5개 사용
- 기존 PPT 삽화는 콘셉트이며, 게임용 스프라이트나 모션 시트로 검수한 자료가 아님
- PC의 Python 3.13 설치 경로에서 pico2d 1.5.1 패키지와 이미지 회전·프레임 잘라 그리기·효과음 음량 함수의 소스 존재 확인
- 프로젝트 .venv 설치와 Windows 창 표시 확인, SDL 오디오 초기화·재생 호출 확인
- 사용자가 실제 키보드 Enter로 시작됨을 확인, 이동·공격 조작감과 출력 장치 청취는 별도 확인 필요, 손전등 암흑 마스크·건물 가림 구현
- Git은 planning/first-presentation 브랜치, 검증된 작업 단위마다 중간 커밋 관리
- 원격은 공개 https://github.com/yoon778/2D_project.git, 업로드 요청 시 작업 브랜치 푸시

사용자의 진행 요청으로 첫 프로토타입 구현 착수
아래 단계별 파일 목록은 구조 초안이며, 실제 첫 실행본은 main.py와 core.py를 중심으로 단순하게 구성

## 2. 개발 방식

**작은 실행본을 만든 뒤 에셋 하나씩 교체**
에셋 전체 제작을 끝내고 게임을 연결하는 순서는 피함

1. 도형으로 이동·벽·배달 확인
2. 캐릭터 원본 한 세트로 장비·회전·공격 표현 확인
3. 전투·좀비·시야·소리를 같은 실행본에 차례로 연결
4. 작동 중인 맵에 바닥·건물·표식 에셋을 하나씩 적용
5. 마지막에 필요한 모션 프레임과 효과음만 보완

매 단계에서 이전 단계의 배달·승패·재시작을 다시 확인
새 기능이 기존 흐름을 깨뜨리면 그 문제부터 수정

## 3. 최초 제작 규격과 공유 기준

아래 크기와 프레임 수는 제안값, 1~3단계 샘플 검수 후 조정 가능

| 항목 | 최초 제안 |
| --- | --- |
| 게임 화면 | 1280×720, 고정 화면 |
| 맵 논리 격자 | 40px 기준 32×18칸, 그림 타일 규격과는 분리 |
| 캐릭터 원본 | 파트별 128×128 투명 PNG, 동일 기준점 |
| 화면 캐릭터 크기 | 약 48~64px에서 가독성 확인 후 결정 |
| 조준 원본 방향 | 모든 파트를 같은 한 방향으로 제작 |
| 회전·이동 | 위치와 이동은 게임 좌표, 몸 방향은 마우스 조준 |
| 충돌 크기 | 그림 크기와 분리, 통로와 실제 샘플을 함께 보며 결정 |
| 속도·공격 간격 | 시간 기준 처리, 화면 프레임 수에 종속시키지 않음 |
| 리소스 경로 | 프로젝트 기준 상대 경로, 다른 PC에서도 동일 |
| 에셋 기록 | assets/SOURCES.md에 생성·출처·사용 조건 기록 |

공유 규칙:
- 게임 좌표는 왼쪽 아래 원점, 마우스 화면 좌표 변환은 입력 경계에서 한 번만 처리
- 원본은 화면 위쪽을 바라보도록 통일하고, 그림 방향과 게임 조준 각도의 보정값을 한 곳에 기록
- pico2d의 이미지 회전축은 이미지 중심, 팔 PNG는 어깨가 중심이 되도록 투명 여백을 맞추고 몸 중심과 어깨 사이 위치 기록
- 같은 건물 데이터로 이동 충돌·좀비 길찾기·시야 가림·공격 벽 차단을 처리
- 좀비 길찾기는 작은 격자의 4방향 BFS부터 검토, 캐릭터 반경과 모서리 충돌도 함께 확인
- 소음 사건은 발생 시각·위치·반경·종류를 전달, 플레이어의 현재 위치를 계속 전달하지 않음
- 논리 판정과 그림을 분리, 이미지 교체가 공격 범위나 충돌 크기를 바꾸지 않도록 함
- 공격 애니메이션의 타격 순간과 실제 피해 판정은 하나의 공격 진행도를 공유
- 낮은 프레임에서도 타격 순간을 건너뛰어 피해가 사라지거나 중복되지 않도록 확인
- 좌우 반전은 사용하지 않고 회전만 적용해 왼손 택배와 오른손 방망이 유지

## 4. 단계별 순서와 의존관계

| 단계 | 작업 | 선행 단계 | 실행 가능한 결과 |
| --- | --- | --- | --- |
| S1 | 환경·기술 확인 | 없음 | 창·입력·회전 이미지·소리·암흑 마스크 확인용 시제품 |
| S2 | 도형 맵·이동·고정 오브젝트·배달 | S1 | V0: 배달 1건과 재시작 |
| S3 | 캐릭터 에셋 원본과 장비 샘플 | S1, 3절 규격 | 한 명의 캐릭터로 회전·장비 표현 확인 |
| S4 | 최소 전투와 기본 모션 | S2 | V1: 때리고 밀어내고 피해를 받는 한 판 |
| S5 | 좀비 길찾기·감지·소음 사건 | S4 | 벽을 돌아오고 소음 발생 위치를 조사 |
| S6 | 암흑 시야·시야 밖 사운드·HUD | S5 | V2: 소리로 경계하고 비춰 보며 배달 |
| S7 | 맵·고정 오브젝트 에셋 적용 | S2·S3 후 제작, S6 후 최종 통합 | 읽기 쉬운 지상 지도 1개 |
| S8 | 모션 보완·리소스 검수 | S3, S6, S7 | 장비·걷기·공격·피격·사망 표현 정리 |
| S9 | 난이도·초기화·실행·제출 준비 | S8 | 다른 환경에서 실행하는 기본판 |

S4는 S3의 완성된 그림을 기다리지 않고 임시 몸·팔 이미지로 시작 가능
S3는 S2와 병행, S7의 그림 제작은 S4~S6와 병행 가능
S7의 추격·암흑 시야를 포함한 최종 통합 검수는 S6 뒤에 진행
화면 통합은 담당자 한 명이 순서대로 진행
S3에서 통과한 원본은 다음 실행본에 바로 적용, S8까지 통합을 미루지 않음

### S1. 환경과 실패 가능성이 큰 기술 확인

배경: 게임 코드가 없는 상태, Python/pico2d 실행부터 검증 필요

예정 산출물: main.py, requirements.txt, 짧은 기술 확인용 코드와 임시 리소스
작업:
- 프로젝트 전용 .venv 준비, 수업 실행 환경과 pico2d 버전 확인
- 창 열기·종료·키보드·마우스 좌표 확인
- 작은 투명 이미지 한 장을 회전해 마우스 방향과 일치하는지 확인
- 효과음 1개 실제 재생과 음량 변경 확인
- 검정 화면 위 부채꼴 가시 영역, 벽 뒤 대상 숨기기를 작은 장면에서 시험
- 화면 가장자리에서도 암흑 마스크 회전·이동 시 빈틈이 없는지 확인

확인: 저장소 루트에서 .venv\Scripts\python.exe game\main.py 실행 후 직접 입력·화면·소리 확인
완료 기준: 프로젝트 환경에서 위 기능의 가능 여부를 확인, 사용한 Python/pico2d 버전 기록
되돌림: 실험 코드는 별도 보관하고 확인된 최소 창 코드만 본 실행본에 유지

### S2. 도형 맵과 배달 V0

배경: 아트 품질과 무관하게 한 판을 먼저 연결하는 단계
선행: S1 통과

예정 산출물: main.py, world.py, player.py, maps/level01.json
작업:
- 바닥·건물·벽을 임시 도형으로 배치
- 거점·목적지·플레이어 시작점 정의
- WASD 이동, 대각선 속도 정규화, 마우스 조준, Shift 달리기
- 건물·맵 경계 충돌과 시야 가림 조회를 같은 지형 데이터로 준비
- E 수령·전달, 성공 화면, R로 위치와 택배 초기화
- 일반 길과 우회 골목을 연결하되 장식은 최소화

확인: main.py에서 거점 수령·벽 충돌·목적지 전달·재시작을 직접 플레이
완료 기준: 그래픽이 도형이어도 배달 1건과 다시 시작이 정상 동작
되돌림: 새로운 장식이나 복잡한 통로를 제외하고 완주 가능한 도형 지도를 유지

### S3. 캐릭터 원본 한 세트

배경: 방향별 그림을 대량 제작하기 전에 조준·장비가 맞는 원본부터 확인
선행: S1과 파트 규격 합의

예정 산출물: assets/characters/의 원본 PNG, 파트 기준점 기록, assets/SOURCES.md
작업:
- 기존 콘셉트를 참고해 게임용 탑뷰 플레이어 한 명과 좀비 한 종류 준비
- 원본은 정수리가 보이는 실제 탑뷰로 제작, 기존 정면 캐릭터 콘셉트를 그대로 회전해 사용하지 않음
- 플레이어 몸, 오른팔·방망이, 택배를 분리 가능한 이미지로 구성
- 같은 원본과 색·비율을 기준으로 생성·수정, 방향별 독립 생성은 피함
- 가슴등과 택배는 몸 기준 위치를 유지, 방망이 팔만 별도 동작
- 실제 화면 크기로 축소한 뒤 마우스를 360도 돌려 검수
- 앞·뒤·옆 이동에서도 손과 상자가 몸에서 떨어지지 않는지 확인
- 택배 소지·미소지와 방망이 준비·타격·회복 3자세를 미리 표시해 파트 겹침과 기준점 검수

확인: 임시 실행본에 한 명만 넣고 회전·이동, 투명 배경·중심축·좌우 손 확인
완료 기준: 두 손 역할이 유지되는 원본 한 세트, 실제 게임 크기에서 식별 가능
되돌림: 파트 분리가 불안정하면 임시 단색 파트를 유지하고 원본 한 장부터 수정

### S4. 최소 전투와 기본 모션 V1

배경: 전투의 재미를 정교한 모션 제작 전에 확인
선행: S2, S3 그림은 선택적으로 사용 가능

예정 산출물: combat.py, player.py·zombie.py, rendering.py의 공격 표현
작업:
- 정지한 좀비 1마리로 거리·각도·벽 차단부터 판정
- 이어서 장애물 없는 공간에서 플레이어를 향해 단순 직선 접근하도록 연결, 뒷걸음과 공격 간격의 체감 확인
- 방망이 팔의 준비·타격·회복 3자세를 시간에 따라 연결
- 한 공격에 적 한 마리, 한 번의 피해, 공격 간격 중 연타 무시
- 피해·경직·사망 후 살아 있는 적의 접촉 피해 처리
- 피격 점멸·잠깐 주춤·사망 시 동작 중단과 사라짐
- 공격 소음 사건 생성 위치와 한 번만 발생하는 시점 준비
- 전투로 인한 성공·실패와 전체 재시작 연결

확인: main.py 직접 플레이, tests/test_combat.py의 의미 있는 판정 테스트
테스트 범위: 한 타 중복 피해·연타·벽 너머 타격·죽은 적 접촉 피해
완료 기준: 기본 모션만으로 공격 타이밍과 적의 반응을 구분하고 한 판 재시작 가능
되돌림: 추가 프레임·화려한 효과를 제거하고 한 타 판정과 간단한 팔 회전 유지

### S5. 좀비 이동과 시야·소음 반응

배경: 전투를 넣어도 좀비의 벽 회피와 감지 기억은 별도 구현 필요
선행: S4, S2의 지도 데이터 고정

예정 산출물: zombie.py, world.py의 보행 경로, 소음 사건 처리
작업:
- 같은 격자와 벽 데이터로 순찰·조사·추격 이동
- 몸 반경을 고려한 통로 통과, 막힌 목표는 수색 후 복귀
- 정면·거리·벽 가림에 따른 발견, 시야가 끊기면 마지막 목격 위치 조사
- 걷기·달리기·공격 사건의 반경과 시각 반영
- 직접 시야를 우선하고 새 소음만 기억 갱신, 보이지 않는 현재 좌표 자동 추적 금지

## 6. 파일 구조 초안

기능이 생기는 단계에서 필요한 파일만 추가, 미리 빈 구조를 전부 생성하지 않음
아래 목록은 game/ 내부 구조이며, 리소스는 main.py 위치를 기준으로 찾아 실행 위치가 바뀌어도 동작하도록 구성
현재 core.py에 이동·충돌·배달·전투를 모아 두었으며, 실제 복잡도가 커질 때만 아래 파일로 분리

- main.py: 시작점·게임 루프·화면 상태
- player.py: 이동·조준·택배·플레이어 상태
- zombie.py: 감지 기억·행동·좀비 상태
- world.py: 지도·충돌·가림·길찾기
- combat.py: 공격·피해·경직의 판정
- rendering.py: 이미지·파트·모션·암흑·HUD 그리기
- audio.py: 효과음 재생·거리별 음량
- maps/level01.json: 고정 지도·거점·목적지·초기 위치
- assets/characters/, assets/world/, assets/ui/, assets/audio/: 실제 실행 리소스
- assets/SOURCES.md: AI 생성과 기존 자료의 출처·사용 조건
- tests/: 전투 중복 피해·벽 가림·감지 기억 등 중요한 논리 테스트만

문법 확인 예시: .venv\Scripts\python.exe -m compileall -q game/main.py game/player.py game/world.py
논리 테스트 예시: .venv\Scripts\python.exe -m unittest discover -s game/tests
위 명령은 해당 파일·가상환경·테스트를 만드는 실행 단계에서 사용, 현재 실행 완료를 뜻하지 않음
