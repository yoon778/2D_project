## 재개 시 계획한 검수 순서 이력

1. 사용자 재개 요청을 확인하고 현재 브랜치·변경 파일·두 담당의 정지 상태부터 확인
2. UI-01 수정본을 실제 창으로 다시 실행해 제목 유지 확인
3. W/D 자동 입력 미반응을 재현·원인 구분하고 이동 입력·해제를 검수, 실제 입력을 확인하지 못하면 미확인으로 유지
4. 벽 접근·우회·앞뒤 가림·포커스 복귀·Esc·창 닫기를 지휘 검수
5. 문제 발생 시 담당 파일에 한정해 수정 요청하고 영향 범위 재검수
6. 지휘 1차 통과 후 중간 커밋, 실행 명령과 3~5개 확인 항목을 사용자에게 인계
7. 사용자 2차 확인과 다음 진행 요청을 받은 뒤에만 R1-B 착수

재개 후 실행 명령은 프로젝트 루트에서 다음과 같음

```powershell
.\.venv\Scripts\python.exe game/main.py
```

위 명령은 인계용 기록이며 중단 중 자동 실행하지 않음

## 재개 검수 진행 기록

- 사용자 `아까 하던거 마저 진행해` 요청으로 R1-A만 재개, R1-B 승인이나 사용자 2차 확인은 아직 없음
- 작업 트리는 재개 전 깨끗했고 보존 커밋 `802da8c`에서 시작함
- 전체 자동 검사 27개 재통과, 문법 검사 재통과
- 네이티브 창에 이벤트 관찰기를 붙여 W·Esc 자동 입력을 재시도했으나 pico2d 반환 키 이벤트는 없었음
- 이 관찰기는 당시 pico2d 필터 후 이벤트만 기록했으므로 raw SDL 미도달을 확정하지 않음
- 네이티브 AX 닫기 버튼은 SDL_QUIT 이벤트와 정상 종료 코드 0 확인
- UI-01은 프레임 사이 제목 덮어쓰기가 계속 관찰되어 UI-02 재수정 요청
- 한 배치의 포커스 상실·복귀가 현재 flags 검사만으로 누락될 수 있어 UI-03 재현·수정 요청
- UI 담당의 시스템 오류(Bad Request) 후 변경을 보존하고 같은 범위로 1회 재개 요청
- 검수용 앱 내부 SDL 사건 재생은 실제 물리 키보드 검증과 구분하며 사용자 2차 확인에서 실제 조작을 확인할 예정

### 수정한 문제

- UI-02: 프레임 끝 제목 복원 사이에도 FPS 제목이 노출됨. vendor의 get_events 대신 앱의 작은 raw SDL poll을 사용해 제목 갱신 경합 제거
- UI-03: vendor가 포커스 사건을 버려 같은 배치 상실·복귀 때 누름 상태 잔류 가능. FOCUS_LOST 즉시 pressed 초기화
- 기존 core·속도·지면 좌표·캐릭터 규격·한 방향 범위는 유지
- 짧은 DOWN/UP가 같은 프레임에 끝나는 경우 이동 0은 연속 누름 샘플의 알려진 특성으로 기록, 탭 보정 기능 추가 안 함
- 독립 최종 읽기 검토에서 추가 필수 수정 없음

### 자동 입력 도구의 한계

CUA의 `w`, `Shift_L+w` 호출은 실제 게임 창에서 raw SDL_TEXTINPUT(771)만 발생했고 KEYDOWN/KEYUP은 없었음. 같은 시점 INPUT_FOCUS=True를 확인했으므로 이 자동 호출로 WASD 물리 입력 통과·실패를 판단하지 않음. Windows SDL 큐 재생 결과와 사용자 실제 입력 결과를 구분함
