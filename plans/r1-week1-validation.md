# 1주차 전체 마무리·실행 품질 검수

기준일: 2026-11-05
사용자 `1주차 작업을 모두 차례차례 진행하고 실제 게임처럼 부드럽고 렉/기타 문제 검증` 요청 반영
현재 S2의 세 방향을 순서대로 끝내고 아래 R1 통합 검수를 수행한다. 사용자 추가 승인 없이 1주차 내부 보완 진행 허용
2주차 R2 전투는 이 요청 범위에 포함하지 않는다

## 완료할 범위

1. S2 나머지 세 방향 보행 8장 제작·게임 적용·방향별 지휘 검수·중간 커밋
2. R1 전체: 사선 시점·4방향 조준/보행·90px/s 이동·대각 정규화·벽/월드 충돌·후진/옆걸음·깊이·포커스 해제·종료
3. 실제 main.run Windows SDL 실행 루프의 프레임 시간·입력 사건·자원 사용 측정
4. 발견한 재현 오류만 담당 채팅에 수정 요청·영향 재검수·커밋
5. 사용자에게 실행본·미리보기·실제 수치·남은 수동 확인을 전달

## 성능·동작 측정

- 더미 드라이버의 단위 검사와 실제 Windows SDL 렌더/시간 측정을 구분
- OS 화면 방해를 피한 숨김 창을 사용하며 SDL renderer/video driver·vsync 플래그·환경·측정 시간을 기록
- main.run의 실제 perf_counter와 dt를 유지. 프레임 시간을 고정하거나 sleep으로 60FPS를 만든 결과를 실성능으로 보고하지 않음
- warmup 이후 약30초의 정지·걷기·방향 전환·벽 접촉/우회·입력 해제/포커스 사건을 재생
- update/draw·Present 대기·프레임 간격을 분리해 median/p95/p99/max, 33.3/50ms 초과 횟수·50ms dt clamp를 기록
- 60FPS의 16.67ms 프레임 예산과 비교하되 숨김/다른 앱 부하·디스플레이 주사율 한계를 함께 기록
- 시작 시 이미지/폰트 로드와 프레임 중 재로드·자원 누적·종료 정리를 확인
- 실제 SDL 큐 사건을 실제 main.run에 전달하고 프레임/좌표/정지/방향의 관찰 결과를 비교
- 숨김 창의 focus surrogate를 사용하면 명시. 물리 키보드/OS 포커스 전환 검수로 바꾸어 기록하지 않음
- 현재 R1 장면의 결과이며 향후 좀비·전투·맵 추가 성능을 미리 보증하지 않음

성공 기준: 실제 입력 연결/충돌/가림/종료 회귀 통과, 프레임 중 이미지/폰트 재로드 없음, 재현 가능한 장시간 정지/자원 누수 없음
프레임 예산 초과는 빈도·발생 위치를 분석해 게임 코드 원인이 재현될 때만 최소 수정
검사 횟수만으로 `렉이 전혀 없다` 또는 사용자 주관적 부드러움 확정 표현을 쓰지 않음

## 담당·검수 스킬

UI는 현재 방향 에셋을 계속 담당, 로직은 별도 실제 루프 검수 adapter 준비 가능
지휘가 네이티브 성능 실행·시각 검수·원인 분리·수정 요청·Git 담당
기존 웹 benchmark/UIA 스킬의 범위가 달라 pico2d-native-qa 전용 스킬을 생성·검증해 이 측정에 적용
verification-before-completion의 현재 상태 증거 원칙 적용
전역 스킬 변경은 새 전용 폴더만, 다른 설정·기존 스킬을 변경하지 않음

증거는 output/review/R1-week1/에 저장하고 최종 handoff에 실제 명령·측정 결과·한계를 연결
중간 커밋은 실제 1주차·단계·한글 설명 유지. 푸시는 별도 요청 전 수행하지 않음
