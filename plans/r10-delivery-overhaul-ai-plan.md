> 계획 작성일 2026-11-16 · 조사 기준 커밋 `1fa969d` · 현재 상태 **계획 작성 완료, 구현 착수 전**

## 2. 재미 방향과 먼저 결정할 내용

### 제안하는 한 판

운송장으로 배송 구역 파악 → 트럭 도착과 수령 → 단서를 보고 기믹 선택 → 가까운 적과 거리 조절하며 돌파 → 배송 → 소음으로 달라진 길을 읽고 다음 배송 → 주차된 트럭 복귀 → 승차·출차 → 영수증 결과

플레이어가 잘한 행동을 즉시 알아볼 수 있어야 함. 명중하면 배트 접촉·적 반응·소리가 같은 순간에 발생함. 병으로 유인하면 실제 길에 틈이 생김. 회로를 연결하면 다리가 내려가고 모터 소리를 들은 적이 접근함. 배송할 때마다 송장에 완료 도장이 추가되고 다음 선택지가 보임

### 사용자와 논의할 방향

| 선택 | 중심 경험 | 설계 영향 |
| --- | --- | --- |
| **돌파·생존 배달, 추천 초안** | 기믹으로 큰 무리를 흩트리고 가까운 소수와 싸우며 여러 곳 배송 | 기존 방망이·병·소음·순찰·다리를 함께 활용, 교전 후 이탈 공간 필요 |
| 잠행·퍼즐 배달 | 관찰과 유인으로 전투 횟수를 줄이고 통과 | 긴 수색과 읽기 쉬운 순찰, 전투의 비용을 크게 조정 |
| 다수전 액션 배달 | 많은 좀비를 연속으로 상대하며 전진 | 스태미나·회피·군중 충돌·다중 공격·큰 전투 공간의 추가 설계 필요 |

추천 초안을 검증하는 60~90초 구간을 R10-03에서 먼저 제작함. 사용자에게 재미있는 순간과 반복하기 싫은 순간을 묻고 다음 지역의 난이도·전투 비중을 결정함

잠정 기본값은 다음과 같음

- 첫 통합 시안은 4번 계약 2개 배송지와 동일 트럭 귀환, 목표 플레이 시간 3~5분
- 전체 개편에서는 1·2번도 2곳 이상, 3·4번은 3곳 배송 후보로 구성
- 첫 경직 0.70초, 배트 70px·전방 ±30도·범위 내 다중 명중은 비교 기준
- 주인공 머리 위에는 가능한 행동 1개와 진행 막대를 우선 표시
- 승차는 E 0.7초 유지 후보, 읽기/설정 중 일시정지, 트럭 연출은 Enter 생략 후보
- 타격음 음색·스윙 모양·교전 난도는 사용자 체감 확인 대상

이 값들은 단계별 비교로 조정함. 이번 요청의 산출물은 계획이며 실제 구현은 후속 개발 요청에서 착수함

## 4. 공통 실행 규칙과 검수 초점

- 프로젝트 루트에서 작업, 기존 `planning/first-presentation` 유지, 지휘만 stage/commit 수행
- 로직 담당은 월드·배송·전투·소음, UI 담당은 그림·모션·화면·음악 에셋 담당. `game/main.py` 연결 수정은 단계마다 한 명에게만 배정
- 코드 작업 전 해당 단계의 파일·입출력·완료 조건을 공유함. 빈 모듈과 전 방향 에셋을 일괄 선제 제작하지 않음
- 기능 묶음마다 지휘 1차 검수와 수정, 한국어 Conventional Commit, 사용자 2차 확인 순서
- 검증 출력은 `output/review/r10-<단계>/`, 실행 리소스는 `game/assets/`, 제작 원본/출처는 `art/`에 저장
- CUA 없이 순수 로직 검사와 숨김 Windows SDL 입력/렌더/믹서 검수. 실제 청취·조작감·재미는 사용자 검수로 기록
- 사용자가 플레이 중인 창/저장 상태를 유지하고 검수용 `LOCALAPPDATA`는 임시 경로로 분리
- 실제 변경에 관련된 테스트만 우선 실행하고 전체 회귀는 월드 상태 통합/최종 ZIP 단계에서 수행

특히 확인할 다섯 가지는 다음과 같음

1. E를 길게 누른 상태에서 메뉴나 쪽지를 닫아 다음 행동이 자동 실행되는 입력 누출 — R10-04
2. 마지막 배송·승차·피격이 같은 프레임에 발생하거나 연출을 생략해 성공이 중복되는 상황 — R10-05/08
3. 병 소진·기믹 조기 사용·문 안쪽 적 끼임으로 진행이 막히는 상황 — R10-06
4. 연속/다중 명중 때 효과음·판정·경직이 중복되거나 무한 정지하는 상황 — R10-01/02/03
5. 이전 해금 저장·계약 순서·재시작·패키지 리소스 누락 — R10-05/07/11

## 5. 상태와 담당 간 연결 규격

아래 이름은 구현 시 사용할 제안 API임. 현재 존재하는 API는 3절에 표시됨. 검증 가능한 더 작은 변경이 있으면 지휘가 이름·호출부를 함께 수정함

### 배송 상태와 트럭

- `DeliveryWorld.mission_phase`는 `arriving`, `unloading`, `delivering`, `returning`, `departing`, `finished`, `failed` 중 하나
- `result`는 기존 `playing/delivered/defeated`를 유지함. `finished`에 진입할 때만 `delivered`, 체력 소진은 `failed/defeated`
- `phase_elapsed`는 월드가 소유함. `advance_route_sequence(dt)`가 연출을 전진시키며 일시정지/포커스 손실 때 dt=0 사용
- 진입/출차 중에는 연출 시간은 진행하고 전투 시간은 정지. `active=False`를 연출 시간에도 그대로 적용해 트럭이 영구 정지하지 않도록 두 업데이트의 호출 조건을 구분
- `skip_route_sequence()`는 진입/하차 연출의 최종 상태 또는 이미 승차한 출차 연출의 최종 상태로 이동. 배송 개수·택배 지급·해금은 정상 재생과 동일
- `DeliveryContract.truck_position`과 `truck_door_position` 추가 후보. `return_point` 기존 호출은 트럭 문 좌표를 사용하도록 한 곳에서 연결
- 주차된 트럭은 한 판 내 같은 위치. 4번 북쪽 안전지점은 **선택 가능한 추격 회피 경유지**로 사용하며 필수 방문/자동 성공 조건을 제거
- 트럭 문 접지점은 차체 충돌 영역 밖에 두고 플레이어 반경만큼 여유를 확보. 주차/출차 시 차체 충돌·빛 차단·길찾기 캐시를 동기화하며, 맵 밖으로 나가는 연출 좌표는 플레이어 지면 이동의 경계 제한과 구분해 처리
- 트럭 문은 `DeliveryWorld._available_interaction()`에 `board_truck`으로 연결. 기존 E 유지/이동·피격 취소를 재사용
- 모든 배송이 끝나야 승차 가능. 승차 완료 프레임까지 체력 0 우선. 출차 시작 뒤에는 연출 상태로 들어가 전투 시뮬레이션을 정지하고 결과를 한 번 확정
- 트럭 근처 위협 판정은 지역 기준으로 시험함. 후보는 문 100px 안에서 플레이어와 시야가 열린 추격자. 먼 골목의 추격자 한 명 때문에 영구 승차 불가가 되는지 검수
- `game/truck_sequence.py` 신설 후보는 위치 보간과 자세 선택만 담당. 배송 상태 변경과 보상 저장을 그림 코드에 넣지 않음

### 여러 택배의 표현

- 기존 `completed_stops`와 `remaining_stops`를 사용. 각 배송을 한 번만 완료 처리하고 배송 순서는 자유
- 트럭에서 해당 계약의 물량을 한 번 수령. 남은 배송이 있으면 왼손 대표 상자 유지, 마지막 전달 후 빈손 표시
- 한 곳 전달마다 송장에 완료 표시와 남은 개수 갱신. 택배 수량은 계약 데이터에서 계산해 별도 중복 상태를 줄임
- 새 배송지는 내부 식별자를 고정함. 기존 배송 객체를 대체할 때 `has_patrol`과 기존 계약의 참조 비교를 함께 수정
- 현재 `can_close_shutter()`와 `_bridge_interaction_in_reach()`의 `returning` 조건을 지역 활성 조건으로 분리. 해당 지역이 활성화된 `delivering/returning`에서 열쇠·쪽지·셔터·회로를 사용할 수 있어야 자유 방문 순서가 성립함. 물체 렌더·지도·병 던지기 힌트에도 같은 활성 조건 적용
- 기존 `two-stop.unlocked`는 후속 묶음 계약 해금으로 읽음. 해금 파일이 있는 사용자는 계속 진입 가능
- 성공/해금 저장은 출차 완료의 최초 `playing → delivered` 전이에서 처리. 재시작은 배송·문·회로·병·소음 예약·연출·입력 상태를 초기화

### 표시와 상호작용

- `InteractionPrompt(key, label, world_position, hold_progress)` 형태의 표시 전용 데이터 제안
- E 행동은 `_available_interaction()`, F 행동은 `nearby_bottle`, 쪽지는 `can_read_bridge_note()` 결과에서 생성
- 우선순위는 진행 중 유지 행동 → 가능한 E → F. 거리·벽·활성 조건은 실제 실행 조건과 공유
- 머리 위 앵커는 현재 스프라이트의 발점과 실제 표시 높이로 계산하고 화면 상단에서 안쪽으로 제한
- Q 던지기와 이동/조준 설명은 Esc 조작 그림에 포함. 행동 후보가 없으면 머리 위 표시를 숨김
- 일반 플레이의 Esc는 일시정지 메뉴, 열린 지도·쪽지·회로는 Esc 1회로 해당 화면을 닫음. 포기 확인창의 Esc는 취소
- 모달 전환 프레임은 입력을 소비하고 다음 행동에 넘기지 않음. 이전에 눌린 이동키·마우스·E 유지 상태를 정리

## 8. 완료 판단

기술 완료는 모든 계약에서 다중 배송과 지역 기믹을 거쳐 동일 트럭으로 귀환하고, 입력·승패·저장·패키지가 일관되게 동작하는 상태

재미 확인은 사용자 플레이에서 타격 성공을 소리/동작으로 알아채고, 적 접근에 따라 싸움/기믹/우회를 선택하며, 다음 배송과 트럭 귀환을 이해하는지 판단함. 자동 완주와 이미지 검수만으로 재미 개선을 완료 표시하지 않음

실패하면 해당 구간의 적 배치·소리·동작·이동 거리를 다시 조정하고 같은 기준 장면에서 비교함
