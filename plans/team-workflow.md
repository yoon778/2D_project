# 그림자 배달 채팅 협업

확정일: 2026-11-03
사용자 요청: 지휘가 로직 개발과 UI·에셋 채팅을 연결하고, 결과 점검·수정 요청·더 나은 방안 제안을 담당

## 역할과 소유권

| 역할 | 담당 |
| --- | --- |
| 그림자 배달 · 지휘 | 사용자 요구 해석, 범위·순서 결정, 두 채팅 연결, 검수·수정 요청, 기획·일정·Git |
| 그림자 배달 · 로직 개발 | game/core.py, game/spatial_audio.py, game/requirements.txt, game/tests/test_core.py, game/tests/test_spatial_audio.py |
| 그림자 배달 · UI·에셋 | game/main.py, game/visibility.py, game/assets/, 새 렌더·시각 검증 |

두 개발 채팅은 같은 2D_project 폴더를 사용하며 파일 담당을 분리
main.py의 입력·로직 연결·소리 소비·종료 처리는 UI 담당, 필요한 동작·공개 API는 로직 담당이 지휘를 통해 전달
개발 채팅은 지휘의 작업 지시를 받고 진행하며 임의 기능 추가·대규모 구조 변경·담당 밖 파일 수정을 하지 않음

## 작업 흐름

1. 지휘가 목적·담당 파일·연결 규격·완료 기준을 담아 작업 지시
2. 로직·UI 담당이 연결에 필요한 조건과 변경 영향을 지휘에 보고
3. 지휘가 차이를 조율한 뒤 담당 파일별로 구현 진행
4. 담당자가 변경 파일·검증 결과·남은 한계·다른 담당에게 필요한 연결을 보고
5. 지휘가 실제 변경과 실행 증거를 점검하고 필요하면 수정 요청
6. 검증된 작업 단위마다 지휘가 중간 커밋, 업로드 요청 시 푸시

개발 채팅의 결과는 지휘가 확인·전달하며, 두 개발 채팅이 서로 직접 작업을 지시하지 않음
지휘가 메시지·상태 확인 도구로 두 채팅을 관리하는 범위는 이 프로젝트의 작업 지시·진행 확인·검토·수정 요청
공유 Git 인덱스 충돌을 막기 위해 stage·commit·branch·push는 지휘만 수행
기존 파일·사용자 변경을 보존하고, 과거 중간 작업을 소급 생성하지 않음

## 유지할 연결 규격

- Game.start/restart/step/swing/interact/is_visible/pop_events 공개 API 유지, 변경 필요 시 먼저 지휘에 보고
- 좌표는 왼쪽 아래 원점의 px, 시간은 초, 각도는 rad
- Event(kind, x, y)는 UI가 프레임당 한 번 소비, 상태 판정은 로직 담당
- 손전등 논리 판정과 화면 마스크는 같은 range/half_angle/walls 사용
- SpatialAudio.update(game, focused) 후 이벤트 재생, 시야 판정으로 소리를 차단하지 않음
- 좀비 소리 전용 채널 6·7, 자동 효과음 채널 8~15 유지
- Renderer.close가 SDL 종료 전에 오디오·이미지·텍스처·글꼴 해제
- 택배는 왼손·몸 앞, 방망이는 오른손, 탑뷰·마우스 조준 유지
- 에셋 크기·중심점·장비 위치·프레임 규격은 첫 실제 에셋 적용 전에 합의

현재 게임은 도형 기반 실행본이며, 최초 에셋은 캐릭터 하나부터 적용해 검증한 후 확장
현재 검증 근거는 game/README.md와 개발 계획 참고, 실제 입력·청취와 자동 검증을 구분

초기 검토 결과:
- 추가 Game API 없이 현재 공개 상태와 공격 타이머로 첫 캐릭터 적용 가능
- 재시작 때 Actor 참조가 바뀌므로 UI의 모션 캐시 초기화 필요
- UI가 실제 변위로 보행을 계산하고, 피격 표현이 논리 좌표를 이동시키지 않도록 유지
- 택배는 몸 앞 배치와 회전 검수가 필요하며, 팔·장비 피벗을 먼저 맞출 것
- 몸 64×64px 등 UI 제안은 표시 크기 후보이며 생성 원본 해상도와 구분, 제작·검수 전 확정하지 않음
- 첫 캐릭터 하나부터 적용 후 8방향·수령 전후·공격·피격을 검증하는 순서를 다음 작업으로 제안
- 이번 설정 작업에서는 게임 코드 수정·에셋 생성 없이 두 담당의 읽기 전용 점검과 계약 공유만 수행

- 도달 불가한 옛 플레이어 도형 코드를 정리하고, 새 이미지와 글꼴·오디오를 SDL 종료 전에 해제하도록 검수
- 최종 검증: 39개 테스트, 주인공 렌더 29장, 1,342프레임 앱 자동 입력의 전투·배달·실패·재시작 통과
- 지휘가 원본·8방향·공격·정지/보행/달리기 확대본을 육안 검토하고, 실제 Windows 창의 새 주인공 표시와 오류 로그 없음 확인
- 실제 키보드 조작감과 스피커 청취는 자동 검증과 구분, 게임 창은 시작 화면에서 사용자 조작 대기
